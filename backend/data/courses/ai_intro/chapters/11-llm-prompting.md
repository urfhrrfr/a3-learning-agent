# 大模型与提示词工程

## 学习目标
- 理解大模型、上下文、提示词和工具调用的基本概念。
- 说明 RAG 为什么能缓解幻觉。
- 能设计包含角色、任务、约束和输出格式的提示词。

## 核心概念
大语言模型；上下文窗口；提示词；少样本学习；RAG；函数调用；Agent。

## 重点难点
大模型生成的是高概率文本，不天然保证事实正确。工程系统要加入检索、引用、审核和回退。

## 常见误区
- 提示词写得长就一定好。
- RAG 可以替代所有事实审核。
- Agent 数量越多系统越智能。

## 示例讲解
资源生成系统先检索课程知识库，再让不同 Agent 生成讲解、练习和代码，最后由 ReviewAgent 审核来源与难度。

## 练习题草案
1. 选择：RAG 中检索结果主要提供什么？
2. 判断：大模型回答中的具体事实都可以直接采信。
3. 简答：一个好提示词应包含哪些要素？
4. 代码理解：指出没有引用来源的生成流程风险。
5. 场景题：为课程讲解 Agent 写一个输出格式约束。

## 拓展阅读建议
阅读提示词工程、RAG 架构和工具调用官方材料；具体模型/API 以官方文档为准。

## 实践任务建议
把同一问题分别用自由提问和结构化提示词询问，比较输出稳定性。
