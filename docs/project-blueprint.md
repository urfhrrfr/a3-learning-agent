# A3 项目蓝图：基于大模型的个性化资源生成与学习多智能体系统

## 1. 项目定位

项目建议定位为：面向高校课程的个性化学习资源生成与学习陪伴系统。

推荐课程样例：`人工智能导论`。

选择理由：

- 与赛题“大模型、多智能体、AI 技术融合”的主题一致。
- 容易构造完整高校课程知识库。
- 容易生成文档、思维导图、题库、阅读材料、动画脚本、代码案例等多种资源。
- 可自然展示 Python 实操案例，例如搜索算法、机器学习分类、神经网络入门、提示词工程、RAG 小实验。

一句话演示主线：

> 学生通过自然语言告诉系统自己的专业、基础、目标和困惑，系统自动更新学习画像，由多个智能体协作生成个性化资源、学习路径、练习题、代码实验和多模态讲解，并根据练习结果动态调整下一步推荐。

## 2. 必须实现的比赛能力

### 2.1 对话式学习画像

画像维度至少 6 个，建议实现 10 个：

- 专业与学历层次
- 当前课程与章节
- 知识基础
- 学习目标
- 认知风格
- 学习偏好模态
- 时间预算
- 易错点类型
- 兴趣方向
- 最近学习行为与掌握度

关键要求：

- 不做传统长表单，使用对话抽取。
- 每轮对话后更新画像版本。
- 前端展示“画像变化”，让评委看到系统不是静态问卷。

### 2.2 多智能体协同资源生成

建议实现以下智能体：

- `ProfileAgent`：从对话中抽取画像特征。
- `KnowledgeAgent`：从课程知识库检索相关知识点和来源。
- `PlannerAgent`：制定学习目标、学习路径和资源组合。
- `LectureAgent`：生成课程讲解文档。
- `MindMapAgent`：生成知识点思维导图。
- `QuizAgent`：生成分层练习题和答案解析。
- `ReadingAgent`：生成拓展阅读材料和阅读理由。
- `MediaAgent`：生成视频/动画脚本、分镜和可渲染素材描述。
- `CodeCaseAgent`：生成代码类实操案例。
- `ReviewAgent`：检查事实依据、引用、难度匹配和安全合规。
- `AssessmentAgent`：根据练习结果评估掌握度并调整路径。

资源类型至少 5 种，MVP 建议做 6 种：

1. 课程讲解文档
2. Mermaid 思维导图
3. 分层练习题
4. 拓展阅读材料
5. 多模态视频/动画脚本或短动画
6. Python 代码实操案例

### 2.3 个性化学习路径与资源推送

学习路径需要包含：

- 当前起点诊断
- 章节顺序
- 每一步推荐资源
- 练习与测评节点
- 根据错题或反馈调整下一步路径

前端建议使用时间线展示路径，用资源卡片展示每一步的材料。

### 2.4 加分项建议

智能辅导建议做 MVP 版本：

- 学生在任意资源页可以提问。
- 系统结合当前画像、当前知识点、已生成资源回答。
- 回答包含文字解释、图解 Mermaid、必要时给出代码片段。

学习效果评估建议做 MVP 版本：

- 学生提交练习答案。
- 系统生成掌握度报告。
- 将错题类型写回画像。
- 自动调整推荐资源和下一阶段学习路径。

## 3. 推荐技术架构

### 3.1 前端

- Vue 3
- Vite
- TypeScript
- Vue Router
- Pinia
- Element Plus 或 Naive UI
- Markdown 渲染组件
- Mermaid 渲染组件
- SSE 或 WebSocket 客户端，用于流式输出与生成进度

核心页面：

- `/`：学习工作台
- `/profile`：对话式画像构建与画像面板
- `/generate`：资源生成工作流
- `/resources`：资源库与资源详情
- `/path`：个性化学习路径
- `/tutor`：智能辅导
- `/assessment`：练习与学习效果评估
- `/admin/course`：课程知识库管理，MVP 可隐藏或简化

### 3.2 后端

- Python 3.11+
- FastAPI
- Pydantic
- SQLModel 或 SQLAlchemy
- SQLite 作为 MVP 默认数据库
- Chroma 或 FAISS 作为本地向量库
- SSE 优先用于流式输出和进度追踪
- 大模型 Provider 抽象层，优先接入科大讯飞相关模型或工具；具体模型名、鉴权方式和协议以比赛期间官方文档为准

### 3.3 多智能体协同框架

MVP 建议采用自研轻量编排框架，而不是一开始引入复杂框架。

核心抽象：

```text
AgentInput -> Agent.run() -> AgentOutput
WorkflowState -> Orchestrator -> AgentTrace -> ResourceBundle
```

每个 Agent 必须具备：

- `name`
- `role`
- `input_schema`
- `output_schema`
- `run(state)`
- `trace_event`

每次资源生成必须保存：

- 哪些智能体参与
- 每个智能体输入摘要
- 每个智能体输出摘要
- 检索来源
- 审核结论
- 失败或降级信息

这样前端可以展示“多智能体协作轨迹”，避免系统看起来只是普通聊天机器人。

### 3.4 数据存储

核心表或实体：

- `StudentProfile`
- `ProfileVersion`
- `Course`
- `KnowledgeChunk`
- `GenerationJob`
- `AgentTrace`
- `Resource`
- `LearningPath`
- `QuizAttempt`
- `AssessmentReport`
- `Feedback`

MVP 可以只做单用户或弱登录，重点放在功能闭环。

## 6. 主要问题与风险

### 6.1 范围过大

赛题看起来要求很多，但初赛最重要的是完整可演示闭环。不要先做完整 CMS、复杂权限、真实视频生成平台或移动端。

建议先完成：

画像对话 -> 资源生成 -> 学习路径 -> 练习评估 -> 路径调整。

### 6.2 多智能体容易流于形式

如果只是后端调用一次 LLM，前端叫它“多个智能体”，说服力不够。

必须展示：

- Agent 角色分工
- Agent Trace
- 任务编排顺序
- 每个 Agent 的输入输出
- ReviewAgent 的审核结果

### 6.3 多模态生成难度高

真正的视频生成成本和不确定性较高。MVP 可采用可控方案：

- 生成视频脚本
- 生成分镜
- 生成 PPT 式画面描述
- 用 Mermaid、SVG、Manim、Reveal.js 或前端动画展示短动画
- 如果接入第三方视频生成，再作为增强项

### 6.4 幻觉与事实错误

必须做 RAG 与审核。

每份学术内容建议包含：

- 来源知识点 ID
- 引用章节
- 置信度
- ReviewAgent 审核结果
- “不确定内容”提示

### 6.5 响应时间

多资源生成可能很慢。必须做：

- 生成任务队列或后台任务
- SSE 进度事件
- 局部结果先展示
- 失败资源可单独重试

### 6.6 交付材料容易被忽略

评分中 PPT、视频、文档占 20%，且会影响评委理解功能。需要和代码并行准备：

- 系统开发说明书
- 测试说明书
- 开源组件与 AI Coding 工具说明
- 演示 PPT
- 7 分钟演示视频脚本

## 7. 评分项映射

创新价值与实用性：

- 对话式动态画像
- 多智能体个性化资源生成
- 学习路径动态调整
- 面向高校课程的完整知识库

功能实现及技术要求：

- Python + Vue 可运行系统
- 多智能体编排与 Trace
- 至少 5 类资源
- RAG、防幻觉、安全过滤
- 流式输出和进度追踪

配套文档：

- 需求分析
- 系统架构
- 智能体设计
- 测试说明
- 部署说明
- 开源协议与 AI 工具说明

演示视频与 PPT：

- 7 分钟内展示完整闭环
- 强调评分点，不只展示页面
- 展示生成过程、智能体协作和最终资源效果

## 8. 推荐 MVP 验收标准

达到以下标准即可认为初赛 MVP 具备竞争力：

- 可以本地一条命令启动前后端。
- 至少内置一门完整课程的样例知识库。
- 用户能通过 5 轮以内对话生成 10 维画像。
- 系统能基于画像生成 6 类资源。
- 前端能展示 Agent Trace 和生成进度。
- 生成内容包含来源、审核状态和安全提示。
- 学生完成一次练习后，系统能生成评估报告并调整学习路径。
- 有完整 README、开发说明、测试说明、PPT 大纲和视频脚本。
